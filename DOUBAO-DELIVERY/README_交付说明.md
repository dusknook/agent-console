# 给豆包的评测包 · 交付说明

**原压缩包无法直接提交给豆包工作，所以这里提供四种纯文本形态** —— 外加一种「贴网址」的形态。
内容全部由运行中的真实服务现场派生（契约 56227 字节，逐字节可复现），非手抄。

---

## 先决定用哪一版

| 场景 | 用这个 | 大小 |
|---|---|---|
| **只想让它读懂并开测**（推荐） | `豆包开测版.md` | 45KB |
| 要完整原始材料（含契约全文） | `agent-console-评测包-单文件版.md` | 126KB |
| 上传被截断 / 有大小限制 | `agent-console-评测包-精简版.md` | 70KB |
| 能上传多个文件 | `多文件版/` 里的 7 份（按编号传） | 123KB |
| **只能粘贴文字** | `可直接粘贴的短提示词.txt` + 任意 1～2 个附件 | 3KB |

**建议路径**：先给「开测版」——它按「豆包要产出什么」组织，读完就能开工。
若对方还要完整材料，再补「单文件版」；若反馈读不全，退到「精简版」。

---

## 开测版 vs 单文件版（值得先说清）

| | 开测版 | 单文件版 |
|---|---|---|
| 组织方式 | 按**产出**组织（你要交什么） | 按**材料**组织（我有什么） |
| 六个评测维度 | **可勾选的检查清单**（26 条） | 散文式说明 |
| 输出要求 | **填空表**（照填即可） | 模板 + 说明 |
| 契约全文 | 不内联（速查表 + 403 原文足够） | 内联在附录 A |
| 体积 | 45KB | 126KB |

两者**数据同源**（都从活契约与同一批证据派生），不会漂移。

---

## 核心提醒（贴给豆包时值得加一句）

这份包的评估对象是一个「**给 AI agent 用的服务**」，所以**评估主体也应该是 AI**。
人类点按钮式的验收在这里系统性失效：人读一句中文就懂了，agent 需要的却是能 `if` 的枚举。

所以请让豆包**以「我是一个要用这套接口干活的 agent」的立场**来评，
而不是「我在评审一份作业」——这两者的结论会差很远。

另外请它**在报告第一段声明是否执行过代码**：
如果只是读文件，那是**静态推演**，可信度和实测不是一个量级 ——
我需要知道哪些结论硬、哪些软。（开测版的「第 0 步」就是为此设计的。）

## 关键数字（现场算的，不是手抄）

- 契约规模：26 路径 / **29 条路由**；被门控 **3** 条
- `error.code` 枚举 **24** 项 · `hints[].action` 枚举 **11** 项
- 幂等四档（从契约数出来）：`safe` 13 / `required` 1 / `optional` 12 / `fingerprint_dedup` 3；其中写端点默认档 `optional` **12** 个（带键即重放首发响应），门控端点按内容指纹去重 **3** 个

## 重新生成（有 Node 22.5+ 才需要看）

```bash
node server.js                      # 服务需在 8787
node tools/make-doubao-package.mjs  # 拉活契约 → 重算速查表 → 重建合并型文本
node tools/make-doubao-start.mjs    # 生成开测版 + 本说明（流水线最后一步）
node tools/make-doubao-site.mjs     # 派生站点（可选，用于贴 URL 通道）
```

服务不可达时会自动退回 `EVAL-PACKAGE/snapshot/` 的快照，并在包头标注来源，不会静默用旧数据。
本文件里的所有大小与数字都由脚本现场计算 —— **硬编码的数字迟早变成谎话**。
