## 归档约定（一次真实的失档与找回）

**换实现之前，先 `mv src/scene.js src/scene-partN.js`，再动笔。**

- 第一部是这么做的 → `scene-part1.js`（32543 B）保留至今。
- 第三部开工时**漏了这一步**，直接 `Write` 覆盖 `src/scene.js` —— 第二部的绘制源码（**62389 B / 1462 行**）当场从工程里消失。

### 排查过程（值得记住的搜索顺序）

1. 按**文件名**搜：`find -name "scene*.js"` → 只有 `scene-part1.js` + 现行 `scene.js`。**扑空。**
2. 按**字节数**搜：全盘 `-size 62389c`。**扑空。**
3. 按**内容**搜：`grep -rl 'idem_keys\|contract_digest\|verify-citation'`（全盘会超时，要缩小范围）。
4. ✅ **最后在编辑器的会话工作区里找到了**：

```
C:\Users\30762\.workbuddy\workspace\sessions\<session-id>\
├── .modify_backup_meta\<content-hash>.<basename>     ← 纯文本，内容是【原始绝对路径】
└── modify_backup\<seq>.<a|m>.<content-hash>.<basename>
        a = 文件被新建（快照为空）
        m = 文件被修改（快照 = 【修改前】的完整内容）
```

命中的那一条：

```
29.m.b7328706.scene.js    62389 B     ← 就是它
.meta/b7328706.scene.js   内容: E:\2026-10-03-16-38-27\video\src\scene.js
```

**找回操作**：`cp 29.m.b7328706.scene.js src/scene-part2.js` → `node --check` 通过 →
sha256 前 16 位 `88b9bb4f6cf5e6c9`，11 章时间轴（0.0/3.0/6.0/9.8/13.6/17.6/21.6/25.4/28.6/31.4/34.5/38.0）
与成片逐一对上，确认是**成片那一版**而非中间态。

### 三条结论

1. **`Write` 覆盖不是不可逆的** —— 编辑器会为每次修改留快照。**别急着宣布"丢了"。**
2. **但它是最后一道防线，不是流程。** 正确习惯仍是**改之前先归档**：`mv scene.js scene-partN.js`。
3. **搜不到时换维度搜**：文件名 → 字节数 → **文件内容里的特征串**。第三步才是有信息量的那一步
   （前两步都扑空，因为它们都依赖"文件还在原来的位置"）。

## 管线

```
src/scene.js  ──►  page.html  ──►  无头 Chrome 逐帧出图  ──►  ffmpeg 合成
  (绘画代码)      (画布外壳)      (puppeteer-core + 独显)     (libx264 + AAC)
```

- **确定性**：所有运动都是 `t` 的纯函数 —— 可复现、可断点续渲。
- **零依赖**：不联网、不加载模型、只用系统字体（刻意不引 Google Fonts —— 断网会静默退化成 sans-serif）。
- **素材内嵌**：第三部的 6 张位图走 `data:` URI 内嵌（`src/assets-data.js`），不是外链文件 —— 见下面「第三部踩坑 ③」。
- **必须走独显**：headless Chrome 默认落 Intel 核显。`--probe` 先看 GPU 名，务必是 NVIDIA。

实测性能（本机 RTX 4060 Laptop）：

| 部 | 帧数 | 渲染 | 编码 |
|---|---:|---:|---:|
| 一 | 1458 | ~54s | ~11s |
| 二 | 1140 | ~38s | ~14s |
| 三 v1 | 1350 | **52s**（30–31 ms/帧） | **14.6s** |
| 三 v3 | **1800** | **85s**（37–74 ms/帧） | **21s** |

> 第三部每帧比前两部重（位图合成 + 离屏叠化），但**单帧耗时反而没涨** —— 位图贴图是 GPU 强项，
> 比 §30 那套水彩三层笔刷便宜得多。
> v3 从 1350 → 1800 帧（+33%），渲染耗时 52 → 85 s（+63%）：多的部分是新增的 29 格路由点亮、
> 12 张说明书纸、26 个上浮光斑 —— 都是**低 alpha 的叠加层**，比位图贵、比水彩便宜。

## 复现

```bash
N=C:/Users/30762/.workbuddy/binaries/node/versions/22.22.2-3/node.exe
P=C:/Users/30762/.workbuddy/binaries/python/envs/default/Scripts/python.exe

$N render.mjs --probe                                   # ① 先查 GPU（看到 Intel 就是走错了）
$N render.mjs --sheet=2.7,8.2,19.5,23.6,30.2,37.6 --cols=3 --out=out/check/a.jpg   # ② 接触表巡检
$N render.mjs --frames=0:60.0 --fps=30 --workers=1      # ③ 全片 1800 帧（可续跑）
$P make-bgm.py                                          # ④ 合成 BGM（60s）
$N render.mjs --encode --audio=assets/bgm.wav --out=out/film-60s.mp4    # ⑤ 编码
$P tools/qc.py --dur=60.0 --md=out/qc-60s.md            # ⑥ 客观体检（15 章）
$P "$HOME/.workbuddy/skills/headless-canvas-video-render/scripts/probe_blank.py" out/frames --hz=15 \
   --bounds=4,8,12.5,16,19.5,23.5,28,31.5,35,38.5,42.7,46.7,51.2,54.5   # ⑦ 全片扫空帧
```

⚠️ **换内容前必须清帧**：`--frames` 有续跑机制，已存在的帧会被静默当成"已完成"（帧号按文件名比，不看内容）。
本沙箱里 `rm` 与 `fs.unlinkSync` 都不可靠（回收站机制不可用 + shim 劫持），**用目录改名代替删除**：

```bash
mv out/frames out/frames-v1-45s && mkdir -p out/frames
```

**只改了一小段时不必整片重渲** —— 把受影响的帧挪走再补渲即可（本片 v3 做过两次）：

```bash
mkdir -p out/_redo && for i in $(seq 1758 1799); do mv out/frames/f$(printf %05d $i).jpg out/_redo/; done
$N render.mjs --frames=58.6:60.0 --fps=30 --workers=1 && rm -rf out/_redo
```

（受管工作区内 `[System.IO.Directory]::Delete($p, $true)` 能真删，实测可行；非受管路径仍退回 `mv`。）

## 第三部 v1 踩到并修掉的五个坑

1. **🔴 换成真实立绘 = 主动接受"动画词汇降级"。**
   §65 那套参数化几何角色什么都能动；换成位图后，能动只剩 5 种（bob / 换图 / 淡入 / 推拉 / 光晕），
   全作用在**整块图**上。硬把几何动效套上去得到的不是动画，是**纸片抖动**。
   另外 `bob` 幅度必须比几何角色小一半（`amp ≤4px / per 3.2s`），不然放大到 700px 高就是"整张画在晃"。
2. **🔴 换表情必须交叉淡化，不能直接换 `src`。** 直接换＝alpha 从 1 跳 0，人物当场**闪断**。
   这与「章节硬切露一帧纯背景」是同一个病，只是降到了位图层。改成两条同位置 + alpha 互补。
3. **🔴 `file://` 加载本地图会把 canvas 标记为"污染"，`toDataURL()` 全线失败。**
   `SecurityError: Tainted canvases may not be exported` —— 而**这条管线就建立在 `toDataURL` 上**。
   注意：`img.crossOrigin='anonymous'` 和 `--allow-file-access-from-files` **都不能解除污染**。
   修法：构建期把图转成 `data:image/webp;base64,…` 内嵌成 `src/assets-data.js`（同源，永不污染）；
   无损 WebP 比 PNG 小 25–35%，6 张图共 **3.59 MB**。
4. **🔴「极暗」不能做成纯色。** 遮罩 alpha 做到 1，整帧变成一块纯色（PNG 只有 **67 KB**）——
   那是**黑屏**不是暗场。峰值压到 **0.82**（留 18% 的底），`ink` 从 `#05060f` 改成 `#0b1026`（带色相）。
   结果 S04 分章极差 30.1（CHECK）→ **19.9（PASS）**。
   **判据：最小的帧异常小（67 KB vs 中位 250 KB）＋ 像素标准差接近 0。均值曲线看不出来。**
5. **S09 时间轴超预算（真 bug）+ 两处布局事故。**
   S09 只有 3.5s，但 `6/6 PASS` 要到 3.77s 才出现、末句整段被切掉 → 从 S10 借 0.7s 重排七拍。
   S12 命题文字压在角色头上 → 立绘高度 742→636、两个角色 x 664/1256→612/1308、命题 y 272→190。
   S11 卡片缩到 0.40 飞向分支后 30px 的字变成 12px（等于不可读）→ 卡片**保持原尺寸**，
   改用流动虚线（`setLineDash` + `lineDashOffset`）**指向**落点。

## 第三部 v3 踩到并修掉的三个坑

（前两个是 v1 那五个的延续，第三个是这一轮新踩的）

6. **🔴 判"这帧是不是空的"，不能用文件体积 —— 尤其不能用 JPEG 的体积。**
   我一开始用"逐帧体积异常小"扫空帧（§69 的判据），结果**误报**：开场那帧 JPEG 只有 **46 KB**
   （全片 p02 的 0.8 倍），但同一刻的 **PNG 有 1116 KB**，完全落在正常区间。
   原因：**平滑的深色渐变在 JPEG 的 DCT 下几乎不花码率，在 PNG 的无损压缩下却很贵** ——
   体积是压缩算法的函数，不是内容的函数。
   **修法**：改用**边缘密度**（灰度图相邻像素差分均值）扫全片 —— 判据与格式、亮度都无关。
   脚本已落进 skill：`headless-canvas-video-render/scripts/probe_blank.py`。
   实测 900 帧（15 Hz）命中 30 帧，**全部落在章节边界且每处 1–3 帧** → 这是离屏叠化的固有代价，不是缺陷。
7. **🔴 极暗段的遮罩退场必须早于内容入场**（见上一节「本轮修掉的三个隐形缺陷」①）。
8. **🔴 收尾"整帧叠一层光"的特效要用 0.3s 分辨率亮度曲线验台阶**（同上一节 ③）。
   `+6.4` 的台阶在均值曲线里几乎看不出来，但会直接把该章极差顶出阈值、并污染 p90。

## 第二部踩到并修掉的五个坑

1. **每章第一帧露出一帧纯背景** —— 体检显示 10 个切换点亮度骤降 5–7（视觉上"每章开头闪一下暗"）。
   修法：把上一章最后一帧**离屏渲染后半透明压上来**（`FADE_IN = 0.22s`），硬切变叠化 → Δ 全部 ≤0.4。
2. **`translate()` 之后仍用绝对坐标** —— 收尾章 `0 FAILED` 胶囊被推右一整个屏宽，裁在画面外。
   缩略图上看像"背景装饰"，**只有末帧全分辨率 + 像素分析才抓到**（绿色像素 x 最大到 1919 = 屏幕右边缘）。
3. **深色片亮度口径不通用** —— 首版均值 20.8 / 近黑 85.6%。修法不是调阈值，是抬暗部：
   薄雾 `0.10→0.17`、暗角 `0.46→0.38`、网格 `0.095→0.13`。
4. **第 9 镜 2.4s 塞不下"和解"** —— 表情切换只有 0.1s 等于没有。重排时间轴（s9 2.4→2.8s）。
5. **气泡在文本切换处会闪断** —— 三元表达式换文案会让 alpha 从 1 跳到 0，改成**两条气泡交叉淡化**。
